# graphrag-lab

一个**可评测、可消融**的 GraphRAG 参考实现。

不是"跑通一个 RAG demo"，而是回答一个更具体的问题：

> **纯向量 RAG 在什么情况下会失败？加上什么能把分数拉回来？每一步各值多少分？**

全部结论以评测数字给出。所有语料为程序合成，机构、人名、辖区均属虚构。

## 一、这个项目要证明的三件事

| # | 命题 | 验证方式 | 结果 |
|---|---|---|---|
| 1 | 纯检索对**多跳关系**存在结构性失败，且**加大 top-k 无解** | k 从 1 放大 20 倍观察 recall 饱和点 | ✅ 17%→50% 后饱和 |
| 2 | **混合检索不一定更好**，等权融合可能是负收益 | RRF vs 路由消融 | ✅ 融合使聚合类 92%→51% |
| 3 | **Prompt 对幻觉的抑制可被量化**，而非玄学 | 三版 answer prompt A/B，同时看答对率与拒答率 | 框架就位，待配 provider |

## 二、数据集：先建图，再渲染文档

这是本项目最重要的设计决策。

真实世界是 `文档 → 抽取 → 图`。本项目**反着来**：

```
  合成图谱 (ground truth)
        │
        ├──► 渲染成非结构化文档  ──► 系统的输入
        │
        └──► 直接推导出评测集    ──► 标准答案 + 证据文档清单
```

**带来的好处**：每道题的正确答案和「哪几份文档是证据」都是算出来的，不是人标的。
于是可以计算 **retrieval recall@k** —— 这个指标是整个项目的地基，
没有它，"我的检索变好了"就只是一句感想。

```
实体 197   边 512   文档 326   总字数 128,340   平均每文档 393 字
评测集 109 题 / 10 种能力 / train 39 · dev 27 · test 43
```

### 刻意制造的四类难度

| 难度 | 做法 | 打击的环节 |
|---|---|---|
| **语义干扰段** | 每份招募说明书都含措辞雷同的「风险因素/费用/赎回」章节 | 向量检索：问"最低认购额"会召回几十份**别的**基金的认购章节 |
| **实体别名** | 同一公司用 全称/简称/罗马化名（`岱屿金融服务有限公司` ↔ `Daiyu Financial Services Ltd.`） | 实体消歧：不归并，图就断成孤立点。**已验证 12 道题的答案实体在文档中仅以别名出现** |
| **指代与跨章节** | 大量「本基金」，且基金全称与最低认购额分处第一节与第四节 | 切块策略：切不好就产生孤儿 chunk |
| **不可短路的多跳** | 基金名与「高风险」三字**从不共现于任何单一文档** | 已由 `verify_dataset.py` 形式化验证 |

> `python run.py verify` 会逐条验证上述断言。**它抓到过一次真实的 train/test 划分泄漏。**

## 三、实测结果

复现：`python run.py retrieval --with-extracted`

### A 组　切块策略（recall@1，检索器固定 BM25）

| 题型 | fixed | section | **contextual** |
|---|---|---|---|
| 单跳事实（原词） | 100.0% | 58.3% | **100.0%** |
| 易混实体 | 90.9% | 63.6% | **100.0%** |

**孤儿 chunk 被复现并修复。** `section` 把「本基金最低认购金额为10万新元」切成不含基金名的独立块，
recall@1 掉到 58%；补上文档标题前缀后回到 100%。

> `fixed` 总分与 `contextual` 接近，但机制不同：它的 chunk 更大（486 块 vs 1092 块），
> **碰巧**把基金名和金额装进同一块。文档再长就会失效，而 `contextual` 是确定性的。
> **只看总分会得出错误结论。**

### B 组　检索路径消融（recall@10）

| 题型 | BM25 | Dense | Graph<br>(标准图) | Graph<br>无枢纽阻断 | RRF<br>朴素融合 | Graph<br>(抽取图) | **Routed<br>路由** |
|---|---|---|---|---|---|---|---|
| 单跳事实（3 类） | 100% | 100% | 100% | 100% | 100% | 100% | **100%** |
| 纯语义（无实体名） | 22.8% | 56.1% | 0.0% | 0.0% | 22.8% | 0.0% | **63.6%** |
| 两跳关系 | 61.9% | 81.0% | 70.2% | 70.2% | 82.1% | 66.7% | 70.2% |
| 三跳关系 | 47.2% | 47.2% | 55.6% | 55.6% | 51.4% | 55.6% | **55.6%** |
| **四跳风险穿透** | 45.0% | 31.5% | **90.0%** | 58.9% | 48.3% | 48.3% | **90.0%** |
| 共同董事 | 31.2% | 18.8% | **93.8%** | 93.8% | 72.9% | 93.8% | **93.8%** |
| 聚合计数 | 37.5% | 62.5% | **92.3%** | 92.3% | 51.1% | 92.3% | **92.3%** |
| **总计** | 65.2% | 71.7% | 78.4% | 75.2% | 73.3% | 73.6% | **86.3%** |

```
BM25 65.2%  →  +Dense 70.5%  →  +Graph +路由  86.3%
```

### 五条结论

**① 纯检索对多跳关系存在结构性失败，加大 k 无解**

```
hop4_risk 的 recall 随 k 变化（BM25）
  k=1   k=3   k=5   k=10   k=20
  17%   32%   32%    43%    50%     ← 放大 20 倍，涨 33 点后就不动了
```
关键证据（董事公告、监管名单）与问题**零词面重叠**，永远召不回。

**② 等权 RRF 融合会把分数拉垮**

RRF 只看名次，不看「这一路在这类问题上是否可信」。BM25 对关系类问题返回一堆高排名噪音，
等权融合把图检索的精确结果挤了出去：

```
聚合计数      Graph 92.3%  →  RRF 51.1%   (-41 点)
四跳风险穿透   Graph 90.0%  →  RRF 48.3%   (-42 点)
```

**正确做法不是「都要，加起来」，而是先判断这个问题该问谁。**
级联路由（非融合）把总分从 73.3% 拉到 86.3%。

**③ 阻断枢纽节点值 31 个点**

辖区节点度数 17~25、托管银行 14，而基金只有 5。允许穿透枢纽，
「共用一家托管行的两只基金」就会被判定为存在关联 —— 关系图谱最常见的假阳性来源。
`hop4_risk`：允许穿透 58.9% → 阻断 **90.0%**。

**④ 抽取 F1 高不代表图好用**

规则抽取 F1 **99.8%**，但同一张图跑检索仍低于标准图（73.6% vs 78.4%）。
差距来自**未合并的跨文种别名**。F1 的计算用标准答案的别名索引做了实体对齐，
**掩盖了消歧欠账**；图检索没有这个外挂，路径是断的。

所以报告额外输出 `entity_dedup_ratio`（抽取实体数 / 标准实体数）：
经消歧后 1.17 → **1.08**，剩余 14 个是罗马化别名，只能靠 LLM 裁决。

**⑤ 向量相似度不能单独用于实体合并**

首次跑通时出现：

```
[向量 1.00] Daiyu Capital Management Ltd. == Dixing Capital Management Ltd.
[向量 1.00] Daiyu Capital Management Ltd. == Heming Financial Services Ltd.
```

相似度 **1.00** 却是毫不相干的两家公司 —— `bge-small-zh` 是中文模型，
对纯英文串的表示几乎坍缩到同一点。若只看向量，所有英文公司名会被并成一个节点，整张图作废。

由此确立本项目的核心原则：**单一信号永远不足以触发合并。**
词面判定升级为三值证据（strong / weak / incompatible），
`incompatible` 对向量有一票否决权。该类错合并归零，且拦下 360 对候选。

## 四、架构

```
┌──────────────────────────────────────────────────────────────┐
│ web/index.html  零外部依赖单页（原生 SVG 画关系图，断网可用）    │
│   问答 │ 可点击引用 │ 证据溯源 │ 关系路径 │ 路由与耗时         │
└───────────────────────────┬──────────────────────────────────┘
                            │  FastAPI (src/graphrag/api.py)
┌───────────────────────────▼──────────────────────────────────┐
│ RAGService  —— 评测脚本与 HTTP API 共用同一套装配              │
│  ┌ QueryRouter ───── 规则路由: 属性类 / 关系类 / 聚合类        │
│  ├ RoutedRetriever ─ 级联: 主路先发, 备选补齐剩余预算          │
│  │    ├ lexical: RRF(BM25 + Dense)                           │
│  │    └ graph:   实体链接 → 意图模板 → 多路径枚举 → 枢纽阻断    │
│  └ AnswerGenerator ─ 带引用生成 + 引用回验 + 拒答护栏          │
└──────┬──────────────────────────────────┬────────────────────┘
       │                                  │
┌──────▼──────────────┐      ┌────────────▼───────────────┐
│ chunks + 向量        │      │ KnowledgeGraph (内存)       │
│ BM25(中文混合分词)   │      │  BFS / 多路径枚举 / 溯源     │
│ Dense(ONNX, 离线)   │      │  接口对齐 Cypher 表达力      │
└──────▲──────────────┘      └────────────▲───────────────┘
       └──────────┬───────────────────────┘
        ┌─────────┴──────────────────────────────┐
        │ Ingest: 切块 → 抽取(LLM/规则) →          │
        │         schema 校验 → evidence 回查 →    │
        │         实体消歧(规则/向量/LLM 三级级联)  │
        └────────────────────────────────────────┘
```

### 四个刻意的"不做"

| 不做 | 理由 |
|---|---|
| **不用 Neo4j** | 百级节点、千级边，内存图遍历几十行搞定，零外部依赖。接口对齐 Cypher 表达力，换库只动 `store/graph.py` 一个文件 |
| **不用 LangChain** | 检索逻辑是本项目的核心论点，包进框架就无法做组件消融，面试被追问"这一步发生了什么"也答不上来 |
| **不用 FAISS/HNSW** | 1092 个向量，暴力内积 0.3ms，比建索引还快。引入 ANN 会带来召回率损失这个新变量，干扰消融结论。切换点约在十万级 |
| **不用 rank_bm25** | BM25 一共 40 行。包进第三方库连"为什么 b=0.75"都答不上来 |

## 五、Prompt 工程：把 prompt 当代码管

Prompt 不内联在 Python 里，而是 `prompts/<用途>/<版本>.md` 的版本化文件：

```markdown
---
id: answer/v3_guarded
base: answer/v2_cited
changes: 加拒答护栏；区分"资料没有"与"资料有但不完整"；多跳题要求先列证据链
hypothesis: 陷阱题拒答率应大幅上升；风险是矫枉过正，本来能答对的题开始拒答
---
# system
...
```

`hypothesis` 是刻意设计的：**改 prompt 之前先写下预期，跑完评测再对照。
预期错了比分数没涨更有价值 —— 那说明你对失败模式的理解是错的。**

| 家族 | 演进 |
|---|---|
| `extract_triples/` | v1 朴素 → v2 封闭 schema → v3 few-shot（含 2 个**负例**：套话段落、指代不明） |
| `answer/` | v1 朴素 → v2 强制引用 → v3 拒答护栏 |
| `router/` | LLM 分类器，对照组是手写规则 |
| `resolve_entity/` | 只裁决灰区候选对，不做全量两两比较 |

### 评测必须同时看答对率和拒答率

```
只看拒答率 → 永远回答"资料中未提及"的系统能拿满分
只看答对率 → 从不拒答的系统在陷阱题上全错，但总分未必难看
```

**单看任何一个都能被轻易刷分 —— 这是 prompt 调优最容易自欺的地方。**
`compare_prompts()` 把两者并排放，就是为了堵住这个口子。

### 三个环节的对照基线

| 环节 | 基线（零 LLM） | 意义 |
|---|---|---|
| 抽取 | `RuleExtractor` 正则 | 回答"LLM 比规则强在哪"。**规则在模板语料上 F1 99.8%，但不具外推性** |
| 路由 | 手写关键词规则 | 在窄领域里 LLM 未必赢。**没验证过就上 LLM 是信仰不是工程** |
| 生成 | `ExtractiveGenerator` 直出原文 | 端到端 16.5%（引用命中 77.3%）。**分清是检索好还是模型好** |

## 六、LLM 与向量：都是可切换 provider

### LLM 层（`src/graphrag/llm.py`）

| `GRAPHRAG_LLM` | 说明 | 用在什么时候 |
|---|---|---|
| `claude` | 原生 citations + 严格 schema | prompt 调优、最终对比 |
| `deepseek` | 成本约 1/20 | 日常开发、批量抽取 |
| `ollama` | 本地模型，完全离线免费 | 没有 key |
| `replay` | **只读磁盘缓存，零网络零调用** | **面试演示** |

能力差异不靠 `if provider == "claude"` 散落各处，而是声明在 `CAPABILITIES` 表里，
上层查询后选择实现路径：

| | Claude | DeepSeek / Ollama |
|---|---|---|
| 严格 schema 约束 | 原生 | 只有 JSON mode → 校验+错误回灌重试 |
| 字符级 citations | 原生 | 无 → "标记 + span 回溯对齐" |

**缓存在 provider 之前**，按 `hash(model + prompt + 参数)` 落盘。解决四件事：

1. **演示确定性** —— 现场用 `replay`，不会出现"这次答得不如上次"的当场翻车
2. **评测可复现** —— 分数不随采样漂移，"这版 prompt 涨了 3 分"才是真涨
3. **成本可控** —— 消融实验反复跑十几轮，无缓存就是十几倍开销
4. **降级无硬失败** —— 没设 key 时自动退到 `replay`，别人拿到仓库也能跑通

成本量级：抽取全量语料 < $1（一次性，Batch 再半价）；一轮完整评测 Opus 5 约 $3、Haiku < $1。

### 向量层

| `GRAPHRAG_EMBED` | 装机体积 | 首次运行需联网 | 备注 |
|---|---|---|---|
| `onnx` | ~50MB | ❌ | `bge-small-zh` 量化版 24MB **随仓库分发**，推荐 |
| `st` | 数百 MB | ✅ | sentence-transformers |
| `none` | 0 | ❌ | 退化为纯 BM25，**零依赖兜底** |

`none` 不是降级方案，**它本来就是消融实验的基线行**。副作用是：
即使目标机器什么都装不上，demo 依然能完整演示，只是评测表里 dense 那几列空着。

## 七、运行

### 环境要求

- **Python ≥ 3.10**（唯一硬性要求）

### Windows

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
```

> **关于中文乱码**：`src/graphrag/compat.py` 在启动时把 stdout 重设为 UTF-8，
> 并对旧版 `cmd.exe` 调用 `SetConsoleOutputCP(65001)`。所有文件读写一律显式
> `encoding="utf-8"`、`newline="\n"`，保证 Windows 与 macOS 产出**字节一致**。
> 若仍有乱码，优先使用 Windows Terminal / PowerShell 7。

> **搬到另一台机器**：`.venv/` 不能跟着走（绝对路径 + 平台专属 wheel），
> 依赖必须在目标机重装。但 `models/` 目录可以直接拷贝 ——
> 拷过去后目标机**无需联网**即可使用向量检索。

### macOS / Linux

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python run.py all && python run.py serve
```

## 九、已知缺口

| 缺口 | 现状 | 方向 |
|---|---|---|
| 纯语义题 | recall@10 63.6% | 换更大向量模型 / 加 cross-encoder rerank |
| 路由粒度 | 两跳题上「融合」优于「路由」 | 按题型给融合权重，而非一刀切 |
| 跨文种消歧 | 14 个罗马化别名未合并 | 需 LLM 裁决（已实现，待配 key） |
| LLM 抽取 | 当前报告用规则基线 | 配置 provider 后 `--extractor llm` |
| Prompt A/B | 框架就位，无数据 | 配置 provider 后 `e2e -- --ab` |
