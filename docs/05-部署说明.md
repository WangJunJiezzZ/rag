# 部署到线上

> ⚠️ **HuggingFace 已改政策**：Docker / Gradio Space 需要付费（PRO），
> **Static Space 对所有人免费**。所以走静态方案。

静态版把检索（BM25 + 实体链接 + 图遍历）全部用 JS 重写，跑在访客浏览器里。
与 Python 版逐题校验过：**BM25 分数四位小数一致，路由与图模板 78/78 一致**。

---

## 一、生成静态站（一条命令）

```bash
python run.py build-static
```

产出在 `build/static/`，约 **1.2 MB**：

```
index.html           14 KB   页面
js/engine.js         11 KB   BM25 + 实体链接 + 图遍历的 JS 实现
data/chunks.json    893 KB   1092 个文本块
data/answers.json   141 KB   78 条预录问答（39 题 × 2 种图谱）
data/graph_*.json    99 KB   两份知识图谱
README.md             2 KB   HF Static Space 配置（YAML 头）
```

本地预览：

```bash
cd build/static && python -m http.server 8899
# 打开 http://127.0.0.1:8899
```

## 二、推到 HuggingFace Static Space

1. 打开 <https://huggingface.co/new-space>
2. 填：
   - **Space name**：`graphrag-lab`
   - **License**：MIT
   - **SDK**：选 **Static** → 模板选 **Blank**
   - **Visibility**：Public
3. Create Space

```bash
cd build/static
git init -b main
git add -A
git commit -m "GraphRAG Lab static demo"
git remote add origin https://huggingface.co/spaces/<你的用户名>/graphrag-lab
git push -u origin main
```

推送密码填 **Access Token**（HF → Settings → Access Tokens → New token，权限 `write`），
不是登录密码。

静态站**不需要构建**，推完几秒就能访问。

## 三、也可以放别的地方

`build/static/` 是纯静态目录，除 HF 外还能放：

| 平台 | 怎么做 | 备注 |
|---|---|---|
| **GitHub Pages** | `bash scripts/publish_pages.sh` 后 push | 免费。**但仓库要公开** |
| **Netlify / Vercel** | 拖拽 `build/static/` 文件夹 | 免费，秒上线 |
| **Cloudflare Pages** | 连仓库或直接上传 | 免费 |

> GitHub Pages 免费版需要**公开仓库**。你的 `rag` 仓库历史里有旧 API key——
> **吊销那个 key 之后公开就没问题了**（吊销后它只是一串死字符串）。

### GitHub Pages 具体步骤

```bash
python run.py build-static          # 生成静态站
bash scripts/publish_pages.sh       # 发布到本地 gh-pages 分支
git push origin gh-pages            # 推上去
```

然后在 GitHub 网页上：**Settings → Pages → Source** 选 `gh-pages` 分支 / `/ (root)`。

一两分钟后访问：
```
https://<你的用户名>.github.io/rag/
```

发布脚本用的是 **git worktree**，不切分支——主分支工作区完全不受影响，
不会出现"发布一下把本地改动搞乱了"。

页面里所有路径都是相对的，已验证子路径（`/rag/`）部署正常。
`.nojekyll` 也自动生成了——不加的话 GitHub 会用 Jekyll 处理站点，可能出问题。

## 四、静态版能做什么、不能做什么

**能（全部在浏览器里实时算）：**
- BM25 关键词检索——对**任意**问题都工作
- 实体链接 + 图遍历——关系路径、风险穿透、共同董事
- 查询路由、枢纽节点阻断、多路径枚举
- 39 道预录题的完整问答：答案 + 引用溯源 + 关系图
- 切换「图谱来源」看抽取损失

**不能：**
- 生成预录之外问题的**答案文字**（需要调大模型，静态站没有后端）
- **向量语义检索**（需额外加载 10MB ONNX WASM，对演示页面不划算）

所以：点示例按钮 = 完整体验；自己乱输 = 有检索结果和关系图，没有生成的答案。
页面顶部有说明，不会让访客困惑。

## 六、附：Docker 方案（需 HF PRO 或自己找服务器）

如果你有 PRO，或想部署到 Render / Railway / 自己的服务器，Docker 方案也做好了：

```bash
python run.py prepare-hf --clean    # 生成 build/hf-space/
cd build/hf-space
docker build -t graphrag-lab .      # 本地已验证：39/39 缓存命中，镜像 541MB
docker run -p 7860:7860 graphrag-lab
```

Docker 版是**完整功能**——含向量检索，且能回答任意已缓存的问题。

## 七、一个跨平台的坑（已修）

首次在容器里跑时，本地 39/39 命中的缓存，容器里只有 **29/39**。
包版本、CPU 核数、架构全都一样。

根因：缓存键 = `hash(完整 prompt)`，而 prompt 里含**检索到的文档**。
检索用 ONNX 做浮点运算，**同一份代码在 macOS 与 Linux 上 top-k 排序会有细微差别**。

> 这不只影响 Docker——**换一台 Windows 电脑同样会中招**。

修法：加一层**语义稳定键**（`prompt版本 + 问题 + 图谱来源 + 模型`），
不含检索结果因而跨平台一致。在线时只认精确键（prompt 改了必须重跑），
离线时精确键未命中才退到稳定键。修完容器恢复 39/39。
