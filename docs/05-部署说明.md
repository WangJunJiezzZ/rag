# 部署到 HuggingFace Spaces

> 最终效果：一个公开链接，面试官点开就能玩，不用装任何东西。
> 服务端完全离线——不调任何 API、不持任何凭据。

---

## 一、先确认本地是好的

```bash
python run.py verify-replay --split train --all
```

看到 `39/39 命中  [PASS]` 才继续。**这一步不过就别往下走**，
否则部署上去也是空白答案。

---

## 二、生成部署目录

```bash
python run.py prepare-hf --clean
```

它会在 `build/hf-space/` 生成一份干净的部署包（约 28 MB）：

| 带上 | 不带 |
|---|---|
| 源码、演示页、prompts | `.venv`（188MB） |
| 向量模型 23MB | `.env`（有 key） |
| 2198 条离线缓存 | `.git` |
| 知识图谱、语料、评测集 | 评测脚本 |
| 文档、评测报告 | `__pycache__` |

脚本会做一次**凭据体检**，发现 `.env` 之类会直接报错退出。

---

## 三、在 HuggingFace 建 Space

1. 注册 <https://huggingface.co>（免费，不要信用卡）
2. 右上角头像 → **New Space**
3. 填：
   - **Space name**：`graphrag-lab`（随意）
   - **License**：MIT
   - **Select the Space SDK**：⚠️ **必须选 `Docker`** → `Blank`
   - **Space hardware**：`CPU basic · 2 vCPU · 16GB`（免费）
   - **Visibility**：Public（要给面试官看就选这个）
4. Create Space

建完会给你一个仓库地址：
```
https://huggingface.co/spaces/<你的用户名>/graphrag-lab
```

---

## 四、推上去

```bash
cd build/hf-space
git init -b main
git add -A
git commit -m "Deploy GraphRAG Lab"
git remote add origin https://huggingface.co/spaces/<你的用户名>/graphrag-lab
git push -u origin main
```

推送时会要账号密码：
- 用户名：你的 HF 用户名
- 密码：**不是登录密码**，是 Access Token
  （HF 网页 → Settings → Access Tokens → New token，权限选 `write`）

推完在 Space 页面能看到构建日志，约 **3~5 分钟**。
看到 `Running` 就成了。

---

## 五、构建失败怎么办

日志在 Space 页面的 **Logs** 标签。常见原因：

| 现象 | 原因 | 解决 |
|---|---|---|
| `no such file: Dockerfile` | SDK 没选 Docker | 重建 Space，SDK 选 Docker |
| `Permission denied` | 平台以 uid 1000 运行 | Dockerfile 已处理，不该出现 |
| 构建超时 | 免费额度构建慢 | 重试一次 |
| 页面能开但答案空白 | 缓存没跟上来 | 本地重跑第一步，再 `prepare-hf` 重推 |

本地想先验证，装了 Docker 的话：

```bash
cd build/hf-space
docker build -t graphrag-lab .
docker run -p 7860:7860 graphrag-lab
# 打开 http://127.0.0.1:7860
```

## 六、这个 Space 能做什么、不能做什么

**能：**
- 点四个示例按钮，完整问答 + 引用溯源 + 关系图
- 切换「图谱来源」看抽取损失
- 切换 prompt 版本对比
- 检索和关系图对**任意**问题都正常工作

**不能：**
- 回答评测集 train 划分之外的问题（会显示「缓存未命中」，
  但检索结果和关系图仍会展示）

想让它能回答任意问题，两条路：

```bash
# 路线一：把 dev/test 也录进缓存（约 4 元，之后永久免费）
GRAPHRAG_OFFLINE=0 python run.py e2e --split dev
GRAPHRAG_OFFLINE=0 python run.py e2e --split test
python run.py prepare-hf --clean   # 重新打包推送

# 路线二：在 Space 里配 API key（HF Settings → Variables and secrets）
#   加 DEEPSEEK_API_KEY，并把 GRAPHRAG_OFFLINE 改成 0
#   ⚠️ 这样任何访客提问都会消耗你的额度
```

**建议走路线一。** 可控、免费、不会被刷。

## 七、一个跨平台的坑（已修，但值得知道）

首次在容器里跑时，本地 39/39 命中的缓存，容器里只有 **29/39**。
包版本、CPU 核数、CPU 架构全都一样。

原因：缓存键 = `hash(完整 prompt)`，而 prompt 里含**检索到的文档**。
检索用 ONNX 做浮点运算，**同一份代码在 macOS 与 Linux 上 top-k 排序会有细微差别**。
排序一变，prompt 就变，键就对不上。

> 这不只影响 Docker——**换一台 Windows 电脑同样会中招**。

修法是加一层**语义稳定键**：只取 `prompt版本 + 问题 + 图谱来源 + 模型`，
不含检索结果，因此跨平台一致。

- **在线时只认精确键** —— prompt 改一个字就该重新调用，否则评测会读到旧结果
- **离线时精确键未命中才退到稳定键**，并在返回值上标记 `alias_hit`

修完容器里恢复 39/39。
