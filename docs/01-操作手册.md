# 操作手册

> 这份文档假设你刚 clone 下来、什么都不知道。照着做就行。

## 一、五分钟跑起来

### 前提：只需要 Python ≥ 3.10

不需要 Docker、不需要数据库、不需要 API key。

### macOS / Linux

```bash
cd graphrag-lab
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py doctor          # 先跑这个
python run.py serve           # 打开浏览器
```

### Windows

```powershell
cd graphrag-lab
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py doctor
python run.py serve
```

**在 Windows 上第一次用 MCP / Agent 部分时，依次跑下面四条确认可用**（全部离线，不花钱）：

```powershell
python run.py verify-mcp                      # 最后一行应为 [PASS] MCP 链路自检通过
python run.py eval-agent -- --split test      # 应复现：答对率 流水线 90%、Agent 100%，共同题数 41
python run.py calibrate-judge                 # 最后一行应为 [PASS]
python run.py build-static -- --strict        # 应显示「Agent 回放 30 条」且没有 [FAIL]
```

`eval-agent` 的输出里如果出现"其中稳定键兜底=N"，是正常的：Windows 上向量检索的浮点结果和录制时的 macOS 略有不同，
这部分由稳定键兜底回放，数字不受影响（见 [05-部署说明 第七节](05-部署说明.md)）。
只有出现 `[FAIL]` 或"缓存未命中"才是问题，把输出发出来排查。

### 端口被占用怎么办

```bash
python run.py serve -- --port 8777
```

`run.py` 后面的参数要用 `--` 隔开，否则会被 `run.py` 自己吃掉。这是唯一一个容易踩的语法坑。

## 三、命令清单

| 命令 | 作用 | 花钱？ | 耗时 |
|---|---|---|---|
| `python run.py doctor` | 环境自检 | 否 | 1 秒 |
| `python run.py phase0` | 生成语料 → 评测集 → 数据自检 | 否 | 5 秒 |
| `python run.py retrieval` | 检索评测（核心那张表） | 否 | 40 秒 |
| `python run.py build-graph` | 规则抽取知识图谱 | 否 | 2 秒 |
| `python run.py build-graph -- --extractor llm` | **LLM 抽取** | **约 ¥1.5** | 13 分钟 |
| `python run.py e2e` | 端到端评测 | 视情况 | 1 分钟 |
| `python run.py e2e -- --ab` | **三版 prompt A/B** | **约 ¥2** | 3 分钟 |
| `python run.py report` | 生成 HTML 报告 | 否 | 1 秒 |
| `python run.py serve` | Web 演示 | 提问时才花 | — |
| `python run.py all` | 除 LLM 抽取外的全流程 | 否 | 30 秒 |
| `python run.py verify-mcp` | MCP 链路离线自检 | 否 | 15 秒 |
| `python run.py mcp-chat` | DeepSeek 通过 MCP 调工具问答（见 [06-MCP](06-MCP.md)） | **是**，每题约 $0.005 | 每题十几秒 |
| `python run.py eval-agent -- --split test` | 固定流水线 vs Agent 评测（见 [07-Agent](07-Agent.md)），默认只读缓存 | 否；加 `--online` 才花钱 | 1 分钟 |
| `python run.py calibrate-judge` | 校准 LLM 判官，默认只读缓存 | 否 | 5 秒 |

**重跑同一条命令不会重复花钱**——所有 LLM 调用都按 `hash(模型+prompt+参数)` 落盘缓存，命中就直接读盘。

## 四、API key 填在哪

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

编辑 `.env`，**只改一行**：

```bash
GRAPHRAG_LLM=deepseek
DEEPSEEK_API_KEY=sk-你的key       # ← 就这一行
```

填完跑 `python run.py doctor` 确认变成 `[ok]`。

`.env` 已在 `.gitignore` 里，不会被提交。

### 四种 provider

| `GRAPHRAG_LLM` | 什么时候用 |
|---|---|
| `deepseek` | 日常开发，便宜 |
| `claude` | 需要原生引用和严格 schema 时 |
| `ollama` | 本地模型，完全离线免费 |
| **`replay`** | **面试演示用这个**——只读磁盘缓存，零网络零调用 |

**没填 key 时会自动降级成 `replay`，不会报错。** 缓存里没有的问题会提示你先预跑。

## 四点五、什么时候会花钱

**就一个开关**：

```bash
GRAPHRAG_OFFLINE=1    # 永不花钱（默认，演示用）
GRAPHRAG_OFFLINE=0    # 允许花钱
```

三个条件**同时**满足才会真正扣钱：

```
  有 key  AND  OFFLINE=0  AND  缓存未命中
```

| 有 key | OFFLINE | 缓存 | 结果 |
|:---:|:---:|:---:|---|
| ✅ | 1 | 命中 | 读盘，$0 |
| ✅ | 1 | 未命中 | **报错，不会偷偷联网**，$0 |
| ✅ | 0 | 命中 | 读盘，$0 |
| ✅ | 0 | 未命中 | **调 API，扣钱** ← 只有这一行 |
| ❌ | 任意 | — | 自动强制离线，$0 |

两个容易误解的点：

- **缓存命中就不花钱，哪怕开着联网。** 重跑同一条命令是免费的。
- **改 prompt 会让缓存失效。** 缓存键 = `hash(模型 + prompt全文 + 参数)`，
  改一个字就是新键。所以 **prompt 定稿后再批量跑**，否则白花钱。

想临时花钱（比如补跑 dev/test 缓存）：

```bash
GRAPHRAG_OFFLINE=0 python run.py e2e --ab --split test
```

## 五、面试当天怎么保证不翻车

演示前一天在有网的环境把要演示的问题**预跑一遍**，结果会进缓存：

```bash
GRAPHRAG_OFFLINE=0 python run.py e2e --ab --split train
```

**然后必跑这一步验证**（这是硬性检查，不是可选项）：

```bash
python run.py verify-replay --split train --all
```

看到 `39/39 命中  [PASS] 离线演示可用` 才算过。
**任何一题未命中，演示时那题的答案区就是空的。**

> 演示页面的 4 个示例题默认从 **train** 划分里挑，与预跑的划分保持一致。
> 若你改用别的划分预跑，记得同步设 `GRAPHRAG_EXAMPLE_SPLIT=<划分名>`，
> 否则示例题会落在没缓存的划分上——首版就踩过这个坑：
> 4 个示例里 3 个落在 dev/test，而缓存只录了 train，点下去全是空白。

演示当天 `.env` 里 `GRAPHRAG_OFFLINE=1`，直接：

```bash
python run.py serve --port 8777
```

这样现场**零网络、零调用、每次结果完全一样**。不会出现"这次模型答得不如上次"的情况。

演示要的是可复现，不是开盲盒。

## 七、常见问题

**Q: Windows 上中文显示成乱码**
A: 先跑 `python run.py doctor`，看"中文输出测试"那行。代码已做了 UTF-8 处理，若仍乱码，改用 **Windows Terminal** 或 PowerShell 7，别用老式 `cmd.exe`。

**Q: `pip install` 卡住或报错**
A: 只有 `onnxruntime` 是必须的（向量检索）。装不上就在 `.env` 里设 `GRAPHRAG_EMBED=none`，退化成纯关键词检索，其他功能全部正常。

**Q: 服务启动很慢**
A: 首次启动要把 187 个文本块向量化，约几秒钟。之后提问是毫秒级。

**Q: 换台电脑要重新下模型吗**
A: 不用。`models/` 目录已经在 git 里，clone 下来就有。

**Q: `.venv` 能拷贝到另一台电脑吗**
A: **不能。** 里面是绝对路径和平台专属的包，换机器必然报错。必须重新 `python -m venv .venv` + `pip install`。

**Q: 数据是真的吗**
A: 事实是真的，文档是程序生成的。角色、关系、口头禅等事实取自维基百科等公开资料（来源见 README 第十节），再由程序按模板渲染成角色档案、名册和剧情梗概，所以措辞不是原文引用。来源互相矛盾的事实一律没收。
