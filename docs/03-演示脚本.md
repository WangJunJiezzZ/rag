# 演示脚本

> 目标：10 分钟讲完，让对方记住**一个结论**——
> "纯向量 RAG 找不全跨文档的关系证据，而且检索指标会骗人；这个人知道在哪、也知道怎么修。"
>
> 下面的话术可以直接念，但用你自己的说法更好。

---

## 演示前 30 分钟检查清单

```bash
cd graphrag-lab
source .venv/bin/activate              # Windows: .\.venv\Scripts\Activate.ps1
python run.py doctor                   # 所有项都要 [ok]
python run.py verify-replay            # 必须 [PASS] 离线演示可用
GRAPHRAG_LLM=replay python run.py serve -- --port 8777
```

**关键：用 `replay` 模式。** 零网络、零调用、每次结果完全一样。
不会出现"这次模型答得不如上次"的当场翻车。

浏览器打开 `http://127.0.0.1:8777`，先自己点一遍四个示例确认都正常。

另开一个标签页打开 `reports/index.html`（评测报告），等下要切过去。

---

## 开场（30 秒）

> "我做了一个 GraphRAG 的检索增强系统，题材是《喜羊羊与灰太狼》和《铁甲小宝》——
> 比如'小灰灰的爷爷是谁'、'小让的爷爷封印过哪个机器人'。
>
> 但我想先说清楚，这个项目**不是为了跑通一个 RAG demo**——那个现在几十行代码就能搭起来。
> 我想回答的是：**纯向量 RAG 在什么情况下会失败？加上什么能把分数拉回来？每一步各值多少分？**
>
> 所有结论我都有评测数字，不是感想。"

**不要一上来就讲架构图。** 先抛结论，再证明。

> 如果对方问"为什么选动画"：事实是公开可核实的，题目大家一看就懂，
> 而且**模型本来就看过这两部动画**——这让"只依据资料作答"变得更难考，后面幻觉那一幕会用到。

## 第一幕：先展示能力边界（3 分钟）

### 点【示例 ①　单跳事实】"灰太狼的口头禅是什么？"

指着屏幕说：

- **答案区**："我一定会回来的"，后面有蓝色的 `[1]`
- **点一下 `[1]`**：右侧证据区自动展开并滚动到对应原文
- **右侧证据**：带绿色左边框的是真正被引用的

> "这一类题，任何一个 RAG 系统都能做对。**真正的差距不在这里。**"

### 点【示例 ②　纯语义】"哪位角色负责管理整片草原？"

> "这道题的问题里**一个角色名都没有**。文档里写的是'青青草原的管理者'，
> 我写了脚本验证过：12 道这类题和语料**没有任何 4 个字以上的重叠**。
>
> 关键词检索在这类题上 recall 只有 33%，向量检索到 75%。答案是包包大人。"

（数字念出来，显得你真测过）

---

## 第二幕：招牌案例（4 分钟，重点）

### 点【示例 ③　关系路径】"小灰灰和小香香是什么关系？"

**等答案出来，然后指着下方的关系图：**

> "系统画出了完整的关系路径：
>
> 小灰灰 ← 母亲 — 红太狼 ← 表妹 — 香太狼 — 女儿 → 小香香
>
> 所以两个人是表亲。"

**然后是最关键的一句，慢一点说：**

> "重点是——**没有任何一份文档同时提到小灰灰和小香香。**
>
> '红太狼是小灰灰的母亲'写在小灰灰的档案里；'香太狼是红太狼的表妹''小香香是香太狼的女儿'
> 写在香太狼的档案里。这是我刻意设计的：**每条关系只写在一份文档里**，脚本验证过。
>
> 关键词检索只能靠堆 top-k 去碰运气。两跳题上，图检索取 5 块就拿全了证据；
> BM25 放大到 20 块，也只有 82%。"

### 讲一个"指标骗人"的真实经历（这一段最加分）

> "但我想讲一个我自己踩的坑。
>
> 我第一次跑端到端评测时，两跳题的**检索 recall 是 100%**——证据文档一份不少。
> 可**答对率只有 25%**，模型一直回答'资料中未提及'。
>
> 我把上下文打出来一看：图检索是按文档轮流发 chunk 的，
> 每份档案**先发出去的是第一块**——'小灰灰 角色档案' 加一行资料来源说明。
> 写着'该角色的父亲是黑太狼'的那一块，根本没进上下文。
>
> recall 是按**文档**算的，只要文档里任何一块被召回就算命中。**指标没错，但它量的不是我以为的东西。**
>
> 修完三处——按问题里的称谓只沿对应的关系走、文档内优先发写着这条关系的那一块、
> 把没用的标题块并掉——两跳题答对率从 25% 到了 85%～90%。"

### 可选：切换图谱来源

把页面上的 **「图谱来源」** 从「抽取图」切到「标准图」，重新提问。

> "我刚才用的是**LLM 从文档里抽取出来的图谱**。现在切到**标准答案图谱**——路径完全一样。
> 我两个层面都量了：抽取的 recall 是 100%，端到端答对率两张图都是 89.7%。
>
> 抽取也不是一开始就这么好。v3 版 prompt 把居民登记、阵营一览这种'标题 + 列表'的文档**整份跳过**了，
> 因为我在负例里写了'不许推理'，模型把'读懂排版'也当成了推理。
> v4 把规则改成'不许臆测，但必须读懂文档结构'，recall 从 86% 到了 100%。"

## 第三幕：幻觉控制（1.5 分钟）

### 点【示例 ④　幻觉陷阱】"懒羊羊的生日是哪一天？"

> "语料里**只有灰太狼的生日**，没有懒羊羊的。同类信息就在旁边，这是最容易张冠李戴的情形。
> 正确行为是拒答。"

**它会说'资料中未提及'，并且指出资料里只有灰太狼的生日。**

> "我的评测集里有 12 道这类陷阱题。有几道是**现实里有答案、语料里没有**的，
> 比如'喜羊羊的妹妹叫什么'——模型本来就知道，考的是它会不会拿记忆来答。"

**然后切换 prompt 版本做对比**（把「生成 prompt」切到 `v1_naive` 重问）：

> "这是没有任何拒答约束的版本——**它同样拒答了**。
>
> 我做了三版 prompt 的 A/B：陷阱题拒答三版都是 100%。
> 最严的 v3 并没有带来收益，反而把可答题的误拒答从 6.2% 推到了 10.3%。
> **更强的约束反而更差**——这个结论我在改 prompt 之前写下的 hypothesis 里就预料到了风险。
>
> 还有一个插曲：第一版报表显示 v2 在陷阱题上'编了两道'。翻原文才发现，
> 它说的是'没有关于卡布达体重的信息'——判分器的拒答关键词里没有这种说法。
> **评测代码本身也要被评测。**"

## 第四幕：切到评测报告（2 分钟）

打开 `reports/index.html`，指着 B 组那张表：

> "这是完整的消融实验。我想讲其中两列——"

**指着 RRF(三路) 和 Routed 两列：**

> "业界默认做法是把 BM25、向量、图三路结果用 RRF 等权融合。
> 我改成了**查询路由**：先判断这个问题该问谁，主路优先出结果，剩余名额才给备选。
>
> 三路融合 92.9%，路由 94.4%。差距主要在关系路径题：90% 对 100%。
>
> 但我想强调对照组的问题：一开始我拿来比的是'BM25 + 图'两路融合，89.7%，
> 看起来路由赢了快 5 个点——**其中一半只是因为多了向量这一路**。
> 消融实验里最容易出错的不是实验组，是对照组。"

## 收尾（1 分钟）

> "最后说两个我觉得比分数更重要的事。
>
> **第一，几个只有真跑才会暴露的 bug。**
> 实体消歧里，'和平星'是'射手座和平星'的子串，首版规则把三颗和平星并成了一颗；
> 修完之后 LLM 抽取又把'卡布达巨人'抽成了实体，和'卡布达'前两个字相同，又被并掉。
> 最后的规则是：**文档里写明的'又名'才是最强证据，子串只算弱证据，交给 LLM 裁决**；
> 另外，同一份文档里有关系边相连的两个名字——比如高圆寺寅彦是高圆寺让的爷爷——一票否决。
>
> **第二，我刻意没做的事。**
> 没用 Neo4j——几十个节点内存遍历几十行就够，引入图数据库是过度工程。
> 没用 LangChain——检索逻辑是这个项目的核心论点，
> 包进框架就没法做组件消融，被问到'这一步里面发生了什么'也答不上来。
>
> 接口都留好了，换实现只动一个文件。"

## 加演：MCP + Agent（3 分钟）

> 对方关心 AI 应用开发、Agent 或 MCP 时加演这一段。原理和追问见 [06-MCP](06-MCP.md)。

**演示前准备：** 全部离线回放，不联网、不花钱，每次结果完全一样。演示前先各跑一遍。

```bash
# 固定流水线：网页演示里「图谱来源」选「抽取图」，提问下面这道题，它会拒答
GRAPHRAG_LLM=replay python run.py serve -- --port 8777
# Agent：同一道题、同一份抽取图谱，它会答对
GRAPHRAG_OFFLINE=1 python run.py mcp-chat -- -q "卡布达搭档的爷爷封印过哪个机器人？"
```

没有终端可用时，直接打开线上的 `agent.html`（回放页面），里面有这两次运行的逐步录像。

### 一句话介绍（30 秒）

> "我把知识图谱做成了一个 MCP Server。MCP 可以理解成 AI 的 USB 接口：
> 数据方做一次 Server，任何支持 MCP 的 AI 应用都能直接接入。
> 下面我用同一道三跳题，对比写死流程的固定流水线，和让 AI 自己调工具的 Agent。"

### 先看固定流水线答错（1 分钟）

在网页演示里，「图谱来源」选「抽取图」，提问"卡布达搭档的爷爷封印过哪个机器人？"：

> "它拒答了，说资料里没提到封印。但我排查过，图谱其实找到了完整的三跳路径。
> 问题出在抽取时多了一条错误的边：它把'卡布达巨人'也当成了卡布达的搭档。
> 这条错误支路带进来一份无关文档，把写着'封印'的那份原文挤出了固定的 8 个检索名额。
> 流水线要求每个结论都有原文支撑，有路径、没原文，它就保守地拒答了。"

### 再看 Agent 答对（1 分钟）

运行 Agent 那条命令，一边等一边指着屏幕上逐行出现的工具调用：

> "同一道题、同一份有错的图谱。Agent 先查卡布达的搭档，再查搭档的爷爷，
> 查到是高圆寺寅彦之后，**它自己决定再查一步**'谁被他封印过'，于是答出了鲨鱼辣椒，
> 三份证据全部引用。这些步骤都是它自己决定的，我只提供了工具。
>
> 但它不是免费的：调了 4 次模型，成本是固定流水线的 12 倍左右。"

### 收尾（30 秒）

> "因为用的是 MCP 协议，同一个 Server 不改代码，
> 就能接到 Cherry Studio、Cursor 这些工具里。
> 一道题说明不了整体。下一步我要在整套评测集上对比：让 AI 自己编排工具，
> 和我原来手写的规则路由，哪类题更好、贵多少。"

**被问到"两次都答对的情况"时**，可以补充案例二（小灰灰和小香香，见 [06-MCP](06-MCP.md)）：
两份图谱都答对，但一次回去读了原文核实、一次没读，成本差 1.6 倍。

**不要演示 MCP Inspector。** 它是调试工具。只有被问到"底层协议长什么样"时，才打开给对方看一眼。

## 如果只有 3 分钟

只讲**示例 ③** + **"recall 100%、答对 25%"那个坑**。这两个就够了：

1. 点示例 ③，展示关系路径，说"没有任何一份文档同时提到这两个角色"
2. 说"图检索 5 块拿全，BM25 放大到 20 块还是 82%"
3. 讲"检索 recall 100% 但答对 25%"，以及怎么定位到标题块

## 翻车预案

| 情况 | 怎么办 |
|---|---|
| 服务起不来 | 直接打开 `reports/index.html` 讲数据，**报告是离线的 HTML，一定打得开** |
| 断网 | `replay` 模式本来就不需要网络。如果你忘了设，`.env` 里改一行重启 |
| MCP 演示报"缓存未命中" | 问题的字必须和脚本里**一字不差**，包括全角问号；缓存是按完整输入匹配的 |
| 被问到不会的 | **直说"这个我没测过"**，然后说你会怎么测。比编一个答案强十倍 |
| 对方质疑"才 42 份文档" | "对，语料小，检索的绝对分数偏乐观，我在 README 的已知缺口里写了。<br>但我只收可核实的事实，宁缺毋滥；项目论证的是各环节的**相对**贡献和失败机制，<br>比如'recall 100% 但答对 25%'这类问题，语料再大也一样会发生。" |
| 对方说"模型本来就知道答案" | "对，所以陷阱题特意挑了现实里有答案、语料里没有的，考的是'只依据资料'。<br>三版 prompt 在这类题上都做到了 100% 拒答。" |
| 对方说"这个 LangChain 几行就能做" | "朴素 RAG 确实几行就能做，我的起点就是那个，80.9%。<br>这个项目讲的是剩下那 14 个点从哪来，以及检索分数到答对之间丢掉的那部分。" |

## 一句话记住

**不要讲你用了什么框架，讲你发现了什么问题、怎么证明的。**
