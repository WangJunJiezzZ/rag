为什么「答对率」和「拒答率」必须并排看：只看拒答率，一个永远回答「资料中未提及」的系统能拿满分；只看答对率，一个从不拒答的系统在陷阱题上会全错但总分未必难看。单看任何一个都能被轻易刷分 —— 这是 prompt 调优最容易自欺的地方。

四、主要结论

  • 纯检索找多跳证据靠堆 k，图检索靠走。两跳题图检索 recall@5 = 100.0%；BM25 放大到 k=20 也只有 82.5%。关系路径题两端角色从不共现于同一文档（verify_dataset.py 已验证）。语料只有 42 份，k=20 已接近半个语料库。
  • 公平对照下，路由仍略优于等权融合。RRF(BM25+Graph) 89.7%、RRF(三路) 92.9%、Routed 94.4%。早期基金语料上"融合把分数拉垮"的结论没有复现；两路融合与三路路由的差距有一半来自向量本身 —— 对照组要对齐。
  • 枢纽阻断的价值取决于查询模板。关系路径题：阻断 100.0% vs 不阻断 90.0%；三跳题 100.0% vs 93.3%。只沿指定关系走的关系链模板本身就绕开了 APPEARS_IN 边，所以差距比无差别扩散时小。
  • 抽取 prompt 的失分点是排版，不是语义。v3 recall 86.2%，居民登记 / 阵营一览整份跳过；v4 把"不推理"细化为"必须读懂列表结构"后 recall 100.0%，precision 98.0% → 96.7%，代价在 hypothesis 里已预先写明。
  • 检索 recall 100% 不代表答案对。首版两跳题检索 recall@8 已是 100%，答对率只有 25%：图检索按原文顺序发 chunk，每份档案先发出去的是标题块。加上关系链模板与文档内挑块后，两跳题答对率 85.0%。recall 按文档算，会掩盖块级缺失。
  • 抽取图与标准图的端到端差距：可答题答对率 89.7% vs 89.7%。v4 抽取 recall 100%，抽取环节在端到端上几乎没有损失。
  • 实体消歧：子串不等于简称，向量不能单独拍板。「和平星」⊂「射手座和平星」、「卡布达」⊂「卡布达巨人」都曾被错并。现在文档声明的「又名」是最强证据；前两字相同的进入灰区交 LLM；同一份文档里有关系边相连的两个名字一票否决。

五、已知缺口

  • 语料只有 42 份文档，检索的绝对分数偏乐观；补充分集剧情时只收可核实的事实。
  • 纯语义题路由后 recall@10 66.7%，纯 Dense 75.0%：融合时 BM25 的噪音把向量的结果挤掉了一部分。
  • 拒答判定仍是关键词匹配：首版漏认了"没有关于……的信息""没有记载"，把正确拒答算成了幻觉；补全措辞、误拒答改为"拒答且没答对"后，三版 prompt 陷阱题拒答均为 100%。新的说法出现时仍会漏判。
  • 列举比较题图检索只有 72.2%：「正义阵营」里的「正义」是字面量，链接不到实体。
  • 枢纽阈值固定为 12，「羊村」这类小枢纽仍会产生弱关联路径。
